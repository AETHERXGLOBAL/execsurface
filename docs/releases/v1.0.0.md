## Supported boundary

The stable v1 support boundary is intentionally narrow:

- Linux x86_64;
- native `ptrace` as the bounded public reference observer;
- prebuilt release artifact qualified for the Ubuntu-24.04 / glibc-2.39-class environment;
- source / crates.io local-build path qualified on Ubuntu 22.04 and Ubuntu 24.04;
- declared Rust source floor: Rust 1.82.

This is not a claim of universal Linux compatibility, ARM64 support, eBPF authority, or backend interchangeability.

## Stable verdict contract

ExecSurface v1 keeps the stable verdict/exit-code meanings:

- PASS = `0`
- ERROR = `2`
- REVIEW = `10`
- BLOCK = `20`

Incomplete, ambiguous, unsupported, or lost evidence cannot silently become PASS.

A baseline remains separate from policy. Backend identity alone does not create semantic authority.

## Target-outcome boundary

The wrapped target command's native exit code or terminating signal remains report metadata rather than a drift-verdict input.

Therefore:

**ExecSurface PASS does not mean the wrapped target command succeeded.**

When target-command success matters, keep the target command as its own CI correctness gate.

## Alpha.6 -> v1 compatibility

The internal RC qualification proved bidirectional profile-4 compatibility:

- an Alpha.6 profile-4 baseline can be consumed by the v1 candidate for unchanged PASS;

- a v1 profile-4 baseline can be consumed by Alpha.6 for unchanged PASS.
