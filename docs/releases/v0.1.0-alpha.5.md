# ExecSurface v0.1.0-alpha.5

Fifth public-alpha candidate, assembled from the immutable alpha.4 public line through the evidence-gated post-alpha.4 promotion program.

## Behavioral-integrity hardening

- adds opt-in Semantics-v3 proof-contract machinery with proposition-bound requirements, fail-closed ambiguity handling, and rejection of empty/underspecified proof contracts;
- preserves baseline-v2/public-default behavior; there is no silent v2→v3 reinterpretation;
- keeps proposition authority explicit: backend names, versions, frequency, similarity, signatures, and attestation metadata do not manufacture semantic authority;
- retains bounded legitimate-variance handling without turning recurrence into authorization;
- retains explicit attestation/provenance bindings without treating cryptographic validity as semantic proof.

## Adversarial verification

The clean candidate was replayed through Semantics-v3 repair and promotion corpora, proposition-authority attacks, attestation substitution attacks, variance-poisoning tests, M11/M12 shared-FD and PATH-TOCTOU adversarial suites on Ubuntu 22.04/24.04, public-surface compatibility, package/install checks, and a final integrated destructive closeout.

## Reproducible release engineering

An initial two-snapshot reproducibility run failed because binaries built from different absolute source roots were not byte-identical. That failure remains retained. The release build recipe now remaps the source root to a canonical virtual path and keeps the original byte-identity criterion. Independent same-environment builds subsequently produced identical binary, crate package, and deterministic bundle hashes.

## Developer experience

- Linux x86_64 remains the bounded public support scope;
- native ptrace remains the public default/reference observer;
- CLI, package install, local GitHub Action PASS/REVIEW/BLOCK/ERROR behavior, privacy sentinel handling, and rollback/default-v2 contracts are regression-tested;
- incomplete, ambiguous, unsupported, or lost evidence remains non-PASS-eligible.

## Explicit boundaries

- eBPF/BPF-LSM work remains research-only/non-default;
- native arm64 portability is not claimed;
- observed behavior is not all possible behavior;
- internal A8 evidence does not close P8 external validation and must not be described as independent external validation.

Publication remains gated by the external-validation boundary and final release readiness. This file is release-preparation material until an immutable `v0.1.0-alpha.5` tag and GitHub Release exist.
